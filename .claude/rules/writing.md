# Writing rules (claims ledger)

- Every number and every claim of consequence must exist in docs/CLAIMS.md with source file and commit before it appears here; otherwise write a [verify] placeholder.
- Never write "first" as a contribution claim. Use the guide's statement: "We study malware detector lifetime under label delay, a fixed analyst budget and conformal drift monitoring in a single time-aware protocol, reported with A-AUT, on Android and Windows PE data."
- Toy, sandbox and fixture numbers are never evidence.
- Threat-landscape statistics carry a source and an access date, or are marked [verify]. Never invent references; check_bib.py resolves every entry.
- Text is a draft for the researcher to rewrite and defend; mark paragraphs that still need their verification. Define every term at first use.
