API reference¶

The public building blocks of the protocol, generated from the docstrings. The command-line interface is described by driftwatch --help and each subcommand’s --help.

Time slicing and the constraints¶

The time slicer: initial training window, then evaluation slots one at a time.

Dataset-agnostic. A SlotSource is anything that can list time slots with their class counts (without touching features) and load one slot’s rows: an in-memory table (driftwatch.data.tables) or the dataset caches (driftwatch.data.presets).

Planning is features-free:

  1. plan_slots() applies the size gate (ADR-0004): a slot is usable only if it is not empty, not partial, and keeps at least min_malware malware after C3 subsampling at the target ratio. Every other slot is skipped with a reason.

  2. plan_windows() carves windows from maximal runs of consecutive usable slots. A window (nT training slots then nE evaluation slots) never contains a gap or a skipped slot. nE=None is the single-run protocol: train on the first nT slots of a run and evaluate on the rest of it.

Iteration is lazy: slice_windows() yields a Window whose training slots are loaded (raw rows), and Window.eval_slots() then loads, subsamples and checks one evaluation slot per step. Each evaluation slot passes C3, C2 and C1 (the constraints module) before it is yielded, so a slot that violates a constraint cannot leave the iterator.

Selectors, policies and monitors must only ever see EvalSlot.public().

Write slot_manifest.csv, window_manifest.csv and slicing_run.json under out_dir.

extra (wall-clock, peak memory, row counts) is stored under run.

TESSERACT constraints C1-C3 as checks that raise (Build Guide section 3; PROTOCOL section 4).

  • C1 (temporal training consistency): every training sample is strictly older than every evaluation sample.

  • C2 (temporal window consistency): an evaluation slot holds malware and benign samples, all from that slot’s own window [start, end).

  • C3 (realistic ratio): the evaluation slot is brought to the target malware ratio by seeded subsampling of malware only. A slot already below the target keeps all its rows and is flagged below_target (“cap and flag”, the researcher’s decision of 10 Oct 2026; ADR-0005 records it). The achieved ratio is therefore never above the target.

Every check raises a ConstraintViolation. None of them warns, and none can be switched off. Never weaken a check to get green: write an ADR and ask the researcher.

The checks take plain arrays. They know nothing about datasets, slots or files, so the slicer and the simulator (which re-checks C1 against the real training pool) share them.

Metrics¶

AUT, A-AUT and the rolling-window geometry of Chow et al. (arXiv 2506.23814v2).

AUT is the guide’s AUT(f, N) = 1/(N-1) * sum_{k=1..N-1} (f_k + f_{k+1}) / 2: numpy’s trapezoid over per-slot F1 with time rescaled to [0, 1], so 1.0 means no decay. TESSERACT arXiv v4 says its published Eq. (4) carried an extra 1/N factor (a typo); this is the form the results rely on (ADR-0006).

A-AUT is (mean, std) of AUT over rolling train/test windows (Eq. 1). The window geometry of the paper, for n slots:

  • nE >= nT (Eq. 2-4): training windows start every nT slots, k = floor((n-nE)/nT).

  • nE < nT (appendix A-E, Eq. 6-8): they advance by nE, k = floor((n-nT)/nE).

Both are stride = min(nT, nE) and k = floor((n-nT-nE)/stride) + 1. The slicer takes the stride as a parameter: ADR-0005 keeps its own strides (LAMDA 3, BODMAS 2) as the headline, and chow_stride gives the paper’s value for the secondary check.

Label delay and the sealed queue¶

The label queue: the only module that knows about the delay d (hard rule 3).

Rule (PROTOCOL.md section 4): a label queried while evaluation slot t is being streamed becomes usable from slot t + 1 + d (d = 0 means the next slot). A slot is scored before any label queried in it exists, so a label can never inform the slot it came from.

Window end (documented rule): evaluation slots are indexed 0..n_slots-1 within a window. A label whose release slot t + 1 + d is >= n_slots has no slot left to inform, so it is ignored and counted in LabelQueue.n_ignored. Windows are independent runs; nothing carries over into the next window.

Sealed labels (hard rule 4): SealedSlot wraps an EvalSlot so that nothing else in sim/ holds the true labels. They leave it by two doors only: the queue’s LabelQueue.query() (which hands them back, delayed, through LabelQueue.release()) and SealedSlot.score() (metric code). Selectors, policies and the pool receive OpaqueSlot views and released rows, never the slot.

Run configuration¶

Run configuration: one strict YAML file per run, and the hash that identifies its results.

Keys follow plan Appendix C (.claude/rules/configs.md): dataset, slots, window (nT, nE, stride), ratio, seeds, model, policy, selector, delay, budget_pct, nonconf, pool, monitors, output. A config either describes the Phase 4 baseline (selector, delay and budget_pct null, policy: never) or a simulation (Phase 5: all three set; policy never or periodic). nonconf adds the conformal layer (Phase 8). monitors (Phase 9) runs drift monitors on the conformal path, and two policies use them: monitor (retrain on the trigger monitor’s alarm) and matched (the matched-count control, whose retrain count comes from a finished monitor run named by source). Monitor settings are frozen in code (addendum v3); the config only names which monitors run. e0 lists the window variants to run (the key keeps its Phase 4 name so that E0 hashes stay valid) and, in a simulation, the same variants apply.

E0 configs hash exactly as they did in Phase 4: to_dict emits the simulation keys only when they are set.

The config hash covers every config value, the code version (git commit, -dirty when the tree has uncommitted changes) and the lock file, so a changed config, change of code or change of package pins gives a different hash.

Detectors¶

The detector interface: fit on one training window, score with a fixed threshold.

  • fit(X, y, window_id) is the only place labels enter. Scoring takes features only.

  • The decision threshold is fixed at construction (default 0.5, ADR-0006). A threshold tuned on data may use only the final training slot, and is passed in here, never learned here.

  • A fitted detector carries the id of the window it was fitted on. Passing another window’s id to predict_proba raises, so a model cannot silently score under the wrong window.

  • Scalers and any other fitted state are built inside _fit from the training rows only.

Conformal layer¶

Class-conditional (Mondrian) conformal p-values and credibility.

For a class c the calibration set keeps the nonconformity scores s_i of the labelled calibration samples whose true class is c. A new sample x with nonconformity s_c(x) for class c gets

p_c(x) = (1 + #{i : y_i = c, s_i >= s_c(x)}) / (n_c + 1)

(build guide section 5, PROTOCOL.md section 4). The comparison is inclusive: a tie counts as “at least as nonconforming”. A class with no calibration sample has n_c = 0 and gets p = 1: nothing in the calibration set says the sample is unusual. The credibility of a sample is the p-value of its predicted class; a low credibility says the sample looks unlike what the model knows for that class.

Validity (P(p <= eps) <= eps for a sample exchangeable with the calibration samples of its class) holds only when the calibration samples are a fair draw from the current data. That is why calibration labels come only from the reserved random slice (recalibrate.py).

Pure numpy; no model code and no labels of the evaluated slot.

Drift monitors¶

One alarm interface for every drift monitor (Phase 9, docs/prereg/addendum-v3.md).

A monitor answers one question per evaluation slot: does slot s look unlike the reference the model in force knows? It is called as monitor.update(view, state) -> Alarm.

  • SlotView is everything a monitor may see of slot s: the public features, the model’s malware probability, and the features of the calibration rows that have already arrived (with their scores under the model in force). It has no label field, and the runner builds it from the label-free OpaqueSlot view, so a monitor cannot reach a held-back label (hard rule 4; spy test in tests/test_sim_sealed.py).

  • MonitorState is the per-(window, seed, arm) state: the reference sample and its slot (rule R, ADR-0010), what the monitor fitted at the start of the window, and a cache of policy-independent statistics.

  • Alarm is the decision with its statistic, p-value and threshold. decided is false when the monitor cannot test (for example too few calibration rows); such a slot never alarms and is counted.

Every random draw (subsamples, permutations, folds) is seeded by (seed, window, slot, role) only, so the same pair (reference slot, current slot) gives the same statistic in every arm that meets it.

Monitors are frozen by addendum v3 and never tuned (CLAUDE.md rule 10).
