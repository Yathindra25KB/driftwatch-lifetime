Licence and ethics audit¶

Prepared 22 Oct 2026 at commit 4e6fbc4 for the capstone hand-in, and updated 27 Oct 2026 for the Phase 12 release (the dependency table now includes the documentation group, and section 5 covers the new scripts; section 6, on the release files, the public history and the GitHub Actions, is new; the former section 6 is now section 7). It covers every dataset and dependency, what the repository redistributes, and a final review that the repository describes how detectors decay and not how to evade them. It is an engineering audit, not legal advice; the researcher decides before anything is published.

3. What the repository redistributes¶

  • Only the synthetic fixture, plus one two-row aggregate table of its run (src/driftwatch/_golden/smoke_table1.csv, shipped in the wheel so that driftwatch smoke works without a clone; a test keeps it equal to the locked golden file). The fixture (tests/fixtures/synthetic/, generated by scripts/make_fixture.py, seeded). tests/test_fixture_regenerates.py checks that it is what the generator writes and that it stays under 1 MB.

  • data/ and results/ are git-ignored; the guard hook blocks git add of either, and tests/test_repo_invariants.py fails if any file under them is tracked (apart from data/manifest.json, which holds hashes and source URLs, not data).

  • Process documents: docs/source/ (the build guide, the implementation plan and the phase prompts: two PDFs and one Markdown file) is no longer tracked: it was removed from the index and added to .gitignore on 22 Oct 2026 at the researcher’s decision, because no licence is stated for those documents. The files stay on the researcher’s disk, and the repository’s history still contains them until it is rewritten, which was not done. .claude/ (hooks, agent definitions, rules) stays tracked as evidence of the guardrails.

  • Tables under reports/tables/ are aggregates of the study’s own predictions (per-arm A-AUT, counts, intervals), not dataset rows.

  • The report quotes short passages (a phrase or a sentence) from abstracts, each with its source and access date in the claims ledger (rows L-01 to L-33); no paper is reproduced.

5. Ethics review¶

Checked on 22 Oct 2026 against docs/ETHICS.md and CLAUDE.md hard rules 1 and 12:

Check

Result

No malware, binary or decompiled code is downloaded, opened, run or redistributed

The code reads pre-extracted feature files only; the only data committed is the synthetic fixture

No evasion tooling and no adversarial-example generation

A case-insensitive search of src/ for evasion, evade, adversarial, perturb, attack, obfuscat, payload and exploit finds no match. The only uses of subprocess run git (code version, tag check)

No network use beyond fetching datasets, checking references and the maintenance scripts

Checked 27 Oct 2026 by searching src/ and scripts/ for urllib, urlopen, requests, httpx, huggingface_hub, gdown, http.client and socket: five files open connections. src/driftwatch/data/download.py fetches the datasets (Hugging Face, Google Drive); scripts/check_bib.py calls Crossref and arXiv; scripts/arxiv_audit.py reads the arXiv API; scripts/dataset_watch.py reads the Hugging Face and GitHub APIs; scripts/zenodo_dry_run.py talks to sandbox.zenodo.org only when run by hand with a token that is read at a prompt and never stored. The development guard allows exactly these hosts (ADR-0001)

The search for evasion terms, repeated on the release files

Case-insensitive search of src/, scripts/, tests/, .github/, .claude/skills/, the architecture pages, the maintenance, release and roadmap pages, README.md, CONTRIBUTING.md, SECURITY.md and CHANGELOG.md for evasion, evade, adversarial, perturb, obfuscat, payload, exploit and bypass, on 27 Oct 2026. Every match is benign: policy text that declines such requests (README, CONTRIBUTING, SECURITY, the issue forms, MAINTENANCE, the extension page), a JSON “payload” in hook tests, a test that perturbs a run to check that a comparison fails, and the guardrail suite’s own “adversarial review” of the guard hook. No evasion or adversarial-example code exists

The issue forms and the contribution policy refuse evasion requests

CONTRIBUTING.md (“Not accepted”), SECURITY.md (“Out of scope”) and the bug-report form say that such requests are declined; the triage playbook tells the maintainer to decline and close them

The text describes decay, not defeat

Chapter 4 section 4.4 describes adversaries at survey level, says the study does not model an adaptive adversary, and contains no recipe; chapter 8 section 8.4 and docs/ETHICS.md say the same

Dual use

Knowing how fast a detector decays and when retraining pays could in principle help an adversary time an attack; the study measures natural drift on public datasets, reports aggregate effects, and offers no method to cause drift. A sentence on this was added to chapter 8.4 on 22 Oct 2026 at the researcher’s decision.

Labels

LAMDA’s labels are antivirus-based with an unpublished scan date [D-16]; BODMAS’s labelling is not described on its project page [D-17]; both are stated as limits in chapter 8

Personal data

None: the feature files describe software, not people

AI-assistance disclosure

Stated in report/ch00_front_matter.md and docs/ETHICS.md; the faculty’s policy is not yet known (docs/PHASES.md)

6. Release files and tools (Phase 12)¶

What a release contains. The wheel and the source archive are built by uv build; scripts/check_release.py (run in the release workflow and by a slow test) opens both and fails on any file under data/, results/, docs/source/, .claude-state/, .venv/ or .cache/, any .env or local settings file, any dataset-shaped file (.parquet, .npz, .npy, .zip) outside the synthetic fixture, any key or certificate, a wheel over one megabyte and a source archive over five. The only data-shaped files that may ship are the synthetic fixture (source archive only) and smoke_table1.csv, a two-row aggregate table of the fixture run that the wheel carries so that driftwatch smoke works without a clone. Built on 26 Oct 2026: wheel 203 kB, source archive 163 kB.

The public repository’s history. The development history contains docs/source/ (course PDFs and phase prompts with no stated licence), which was untracked on 22 Oct 2026 but remains in old commits. The public repository is therefore created from a filtered copy of the history made with git filter-repo --path docs/source --invert-paths, followed by checks that git log --all -- docs/source is empty, that no blob is larger than ten megabytes, and that no secret pattern is present; the mapping from old to new commit hashes is committed (docs/commit_map.csv) so the commits cited in docs/CLAIMS.md stay findable. The step is part of the researcher-gated release procedure and has not been done.

7. Not done here¶

No upload to any package index, no DOI, no change of repository visibility, no filtered public history, no tag, no pending publisher registered. Each of those needs the researcher’s explicit go (docs/RELEASING.md).
